Stylesheet 0.1.0a1

One stylesheet for the nodestep sandbox, nodeartifact, text-to-sql-demo and future projects. This page shows its tokens and components, each with the markup to copy.

Start

Copy nodestep.css, nodestep-theme.js and, for the data viewer, nodestep-data.js next to your pages. Each release has them attached. There is no build step.

Load both scripts in <head>, before the stylesheet and without defer, and your own stylesheet after nodestep.css:

Markup 
<head>  <meta name="color-scheme" content="light dark">  <script src="nodestep-theme.js"></script>  <script src="nodestep-data.js"></script>  <link rel="stylesheet" href="nodestep.css">  <link rel="stylesheet" href="app.css"></head>

nodestep.css declares its version in --nodestep-design-version on :root. To see which version an app has, run grep nodestep-design-version nodestep.css on its copy.

Tokens

Every value is a custom property on :root. Color tokens hold a light and a dark value through light-dark(), so a component never needs a dark-mode rule of its own.

Color roles

accent fills buttons, marks the current item and draws the focus ring. accent-text is for text and links; in the dark theme both have the same value.

Layout

A page is a column of sections. Inside a section, a stack puts things under each other, a cluster puts them in a row that wraps, and a grid makes columns that fold on narrow screens. Each spaces its children with gap only, so their own margins do not add up.

Page column

nodestep-main is the main area of a page: the content width, gutters on both sides and room at the top and bottom. nodestep-page is the same column without that room, and nodestep-page-narrow keeps it at a reading width, as for a chat.

App shell

nodestep-app lays out an app: the top bar across the top, an optional panel at the start and at the end, and the main area between them. Only the page's own top bar sticks, body > .nodestep-topbar or .nodestep-app > .nodestep-topbar; a top bar inside content, like the examples below, stays in flow. Below 75rem the end panel folds behind a button in the top bar, and below 48rem the start panel does too. Narrow the window to try the buttons.

Theme button

One button switches between the light and the dark theme: a moon in the light theme, a sun in the dark theme. Its name stays "Dark theme", and aria-pressed says whether the dark theme is on. Until someone presses it, the page follows the system setting.

Search

The search field is the docs search. Put it first in nodestep-topbar-end, before the other controls. The clear button shows while the field holds text. As type="reset" it empties a field that starts empty, without a script; a page that fills in the query, as the nodeartifact trace list does, makes it a link to the page without the query. The icon is a label, so give the field an id and the icon its for. Below 60rem the field folds to its icon, and pressing the icon opens the field over the top bar. nodestep-theme.js keeps the focus in the field when the clear button is pressed, so the field stays open.

Data viewer

A JSON value as a tree: objects and arrays fold and show how many keys or items they hold, and each value has the look of its type. A list of chat messages reads as one folded row per message: the role, the text on one line, or in full when it is short, and one line per tool call. A click on a row opens the whole message, and its JSON is one more click away. A search opens the rows its matches are in and counts each match once. The markup works without a script; nodestep-data.js adds the search, Expand all, Collapse all and Copy JSON. Search for caramel and press Enter to go from match to match, or Shift + Enter to go back.

nodestep-data.js runs in <head> without defer. It sets data-nodestep-data on <html>, which shows the toolbars, and listens on the document, so viewers added to the page later work as well. The search skips the entries of a message's JSON marked data-nodestep-data-echo, which repeat what the row shows. It writes no styles and no markup strings, so it works under a Content-Security-Policy with script-src 'self'.
